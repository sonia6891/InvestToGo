# ETF 袋著走 全面改版設計

- 日期：2026-11-11
- 狀態：**草案，等使用者審閱**。本文件只記錄已確認的決定與提案；標示「待決定」的項目，在使用者明確同意前都不是定案。
- 視覺示意：[口袋金幣試玩（3D 示意頁）](https://claude.ai/artifact/487rNawBA8gay5GjdFKdzA)，含首頁與費用率細項兩個畫面。

## 1. 目標

把「ETF 袋著走」重做成一個**公開上架、只做 ETF、有 3D 遊戲感**的 App。iPhone 先上，安卓隨後。以「跨券商、專為 ETF、一句話就能問」為主打，提供免費、口袋會員、會員＋AI 三種方案。

成功標準：

1. iPhone 版通過 App Store 審核並公開上架。
2. 使用者不用任何金鑰，下載登入後就能記錄持有與配息、看到官方收盤價。
3. 畫面感覺與 3D 示意頁一致：每頁一個 3D 主角、完成時有爆開、音效與震動、可換皮膚。
4. 訂閱可在 iPhone 購買、恢復，並由伺服器確認狀態。
5. 安卓版之後上架時，同一份測試資料在兩個平台算出相同結果。

## 5. 整體架構

### 5.1 iPhone 工程結構

```
App/                    SwiftUI 畫面與狀態（View / ViewModel）
  Design/               3D 設計系統：場景、方塊數字、口袋與金幣、皮膚、音效、震動
  Features/             各分頁與功能畫面
PocketCore/             Swift Package：純邏輯，不依賴 UI
  Models/               持有、配息、ETF、費用、價格
  Import/               券商 CSV（UTF-8／UTF-16／Big5）、舊版備份
  Analytics/            報酬、回撤、波動、重疊、費用計算
  Sources/              官方收盤價、富果（進階）、公會費用資料的解析
  Backup/               備份檔格式（含版本號）
SharedFixtures/         兩個平台共用的測試資料與預期結果（JSON）
Tests/                  PocketCore 單元測試、UI 測試
```

原則（依 iOS 上架守則）：

- 畫面、狀態、資料存取三層分開；所有網路與 Supabase 呼叫集中在 `Repository` 層。
- 每個網路請求處理載入中、錯誤、無資料三種狀態，錯誤訊息用人看得懂的話。
- 使用者可見文字集中管理，方便本地化。
- 既有 `PocketCore` 邏輯從現有 `Models.swift`、`BrokerImport.swift`、`ResearchData.swift` 等移入並保留既有測試；畫面全部重做。

### 5.2 3D 設計系統

- （依 D7 確認最低 iOS 版本）以 RealityKit 的 `RealityView` 嵌入 SwiftUI，物件用程式產生（方塊拼成的數字、口袋、金幣），不需外部 3D 模型檔；皮膚只換材質與配色。
- 材質：霧面（高粗糙度、無金屬）與亮面金屬（低粗糙度、高金屬），環境光照反射。
- 動態：金幣入袋、碎片爆開、數字彈跳、拖曳轉動；使用者開啟「減少動態效果」時改為淡入淡出。
- 觸覺：Core Haptics 自訂節奏；音效：短音效，可在設定關閉。
- 資料頁：上方 3D 主角，下方遊戲狀態欄風格明細（等寬字、細線），點任一行有輕震動與音效，主角同步變化。

### 5.3 資料來源

| 資料 | 來源 | 金鑰 | 狀態 |
|---|---|---|---|
| ETF 名單 | 證交所、櫃買中心（沿用現有） | 不需要 | 已有 |
| 每日收盤價 | 證交所、櫃買中心開放資料 | 不需要 | **端點需實測**（本開發環境連不到證交所） |
| 年度實際費用 | 投信投顧公會（沿用現有快照） | 不需要 | 已有 |
| 成分股 | 富果（進階）或匯入；官方免費來源待查 | 進階 | 待查 |
| 盤中報價、還原歷史 | 富果（進階選項） | 使用者自行申請 | 已有 |

### 5.4 後端（Supabase `product-workstation` 專案）

- App 的資料表放在獨立 schema `etf`，與網站資料表分開；每張表開 RLS，只允許本人讀寫自己的資料。
- App 內只放 publishable key；Claude、App Store Server API 等密鑰只放 Edge Function secrets。
- Edge Functions：`ai-proxy`（呼叫 Claude、計算並限制使用次數）、`iap-notify`（接收 App Store Server Notifications、更新訂閱權限）、`delete-account`（刪除帳號與所有資料）。
- Schema 變更一律走 migration，破壞性操作先經使用者確認。

### 5.5 訂閱

- StoreKit 2，三種方案；付費畫面清楚顯示價格、期間、自動續訂說明，附使用條款與隱私權政策連結，並有「恢復購買」。
- 訂閱狀態以伺服器（App Store Server Notifications）為準，記在 `etf.entitlements`，安卓日後接 Google Play 也寫入同一張表，達成跨平台通用。

### 5.6 AI

- App 不直接連 Claude，一律經 `ai-proxy`；送出資料前取得使用者同意，隱私權政策列明。
- 只解讀資料與回答事實，不提供買賣建議；限制寫在系統提示與伺服器檢查中。
- 預設模型 Claude Opus 5.5；各功能改用其他模型或設定次數上限，等實測成本後由使用者決定（D9）。

## 6. 帳號與同步（P1 重點）

### 6.1 登入方式
Email 與 Sign in with Apple；若加入 Google 登入，iPhone 版必須同時提供 Sign in with Apple。

### 6.2 審核風險
Apple 對「核心功能不需帳號卻強制登入」可能有疑慮。送審備註說明跨平台同步與訂閱需要帳號，並提供審核用示範帳號。若被退件再討論對策。

### 6.3 刪除帳號
App 內可直接刪除帳號與雲端資料，經 `delete-account` 執行。

### 6.4 加密方式（D8，待決定）

| 做法 | 說明 | 代價 |
|---|---|---|
| (a) 端對端加密 | 資料在手機加密後才上傳，連我們都看不到；需要使用者保管一組「同步密碼／復原碼」 | 忘記密碼就無法還原雲端資料；換到安卓也要輸入 |
| (b) 標準保護 | 傳輸加密＋資料庫靜態加密＋RLS 只允許本人存取 | 技術上管理者能讀取資料，需在隱私權政策說明 |

## 8. 遊戲獎勵（D2，待使用者勾選）

原則：獎勵好習慣，不獎勵買更多或頻繁交易。

連續領息、持有週年紀念、定期定額打卡（只看是否堅持）、一年不亂動、對帳達人、省費達人、體檢完成、ETF 圖鑑（研究即收錄，不必買）、除息季限定皮膚、口袋年報；「累計領息里程碑」待 D11。

## 9. 測試與驗證

- `PocketCore`：單元測試，使用 `SharedFixtures` 的輸入與預期結果；既有 26 項單元測試移植後必須全數通過。
- 畫面：UI 測試覆蓋五個分頁、記錄配息、匯入、刪除帳號、付費畫面。
- 3D：效能檢查（目標 60fps）、「減少動態效果」路徑、VoiceOver 讀出 3D 主角代表的數值。
- 訂閱：Sandbox 與 StoreKit Configuration 測試購買、取消、續訂、過期、恢復。
- Supabase：每次變更後執行 security advisors。

## 10. 風險與限制

1. **iPhone 版需要 Mac 編譯**：本開發環境是 Linux，無法編譯或執行 iOS。現行做法是 GitHub Actions 的 Mac 建置機，10 月時月預算已用完；需確認 11 月預算是否恢復，或由使用者在 Mac 上編譯。安卓部分可在本環境編譯測試。
2. **官方資料端點未實測**：本環境連不到證交所網站，收盤價與除權息端點要在可連線的環境驗證。
3. **強制登入的審核風險**：見 6.2。
4. **法規**：收費內容限於工具與資料整理，不提供投資建議；上架前建議由律師確認。
5. **共用 Supabase 專案**：網站與 App 共用登入系統；D13 完成前不開放註冊。
